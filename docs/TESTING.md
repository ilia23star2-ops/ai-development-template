# TESTING.md — что и как тестируется

> Правило: новый код → новые тесты. См. `RULES.md` §12.3.

---

## Принцип

**Тестируем критичное, что легко сломать молча:**
парсеры, поиск, доменные решения, чистые функции расчётов,
логика БД-операций, миграции.

**Не тестируем:** UI, I/O, реальная БД, системные сервисы,
аудио, камера, сенсоры. Это device-check.

## Правила написания

1. Имя теста — <правило проекта>.
2. Ассерты — простые.
3. Один тест — одна проверка.
4. Не тестировать UI.
5. Тест быстрый.
6. Комментарии — на языке проекта.

---

## Что делать при падении теста

1. Не удалять тест.
2. Тест — контракт.
3. Если тест прав, а код неправ — исправить код.
4. Если тест устарел — обновить с пояснением.
